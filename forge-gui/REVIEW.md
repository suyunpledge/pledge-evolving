# Forge GUI 审查与交互优化记录

审查范围：GUI 配置编辑、功能开关、文件保存、gateway 生命周期及流式对话。

## 已修复的问题

| 级别 | 原问题 | 修复结果 |
|---|---|---|
| P1 | 整理器将通道和路由行当作 Provider，可能改变 id、禁用行或重置路由 | 标准非 Provider 行保持原样；保留 Provider 的 disabled 和元数据；GUI 不自动生成空路由覆盖已有路由 |
| P1 | 保存开关使用内存中的整份旧配置，可能覆盖外部修改 | 重新读取用户层，只应用实际变化的开关，保留其他最新字段 |
| P1 | 读取失败当作空配置，直接写文件可能损坏原配置 | 损坏文件阻止保存；临时文件写入并同步后原子替换；替换前检查配置变化 |
| P1 | 旧编辑预览可能覆盖刚保存的开关 | 根据编辑基线检查受影响条目，变化时拒绝覆盖并要求重新载入 |
| P2 | 按回车绕过禁用按钮，可重复提交；生成时清空会破坏上下文 | 请求状态统一防重入；请求使用上下文快照，成功后在主线程提交历史 |
| P2 | 主线程执行网络探测，可能短暂冻结界面 | 网络检查在工作线程运行，界面显示连接/生成状态，失败后保留重试文本 |
| P2 | 旧 gateway 回调或关闭后的回调可能更新错误状态 | 工作线程通过事件队列交付 UI 更新；进程身份校验；关闭后停止接收更新 |
| P2 | 开关展开、高 DPI 和小窗口使预览或按钮不可见 | 开关独立页面并可折叠、滚动；编辑内容可滚动；保存按钮和状态栏预留空间 |

## 工程心理学原则落实

- 状态可见：每个开关显示选择值与保存状态，汇总待保存数量；明确“保存”和“运行服务读取新配置”的区别。
- 减轻记忆负担：当前状态直接回显，改回原值自动恢复干净状态；保存按钮注明修改数量。
- 防止操作失误：未保存编辑退出或切换条目时提醒；阻止重复请求、过期预览覆盖和损坏配置覆盖。
- 便于恢复：还原未保存开关、刷新已保存配置；失败消息保留以便重试；提供 Forge 目录选择入口。
- 避免无关打断：普通保存使用状态反馈；流式输出在用户上滚阅读时不强制拉回底部。
- 键盘可用：开关显示焦点边框，Notebook 支持 Ctrl+Tab，配置编辑支持 Ctrl+Enter 整理。

## 验证

- `python -m unittest test_gui_review -v`：18 项通过。
- `test_config_model.py`、`test_forge_client.py`、`test_integration.py`：全部通过。
- Python 编译检查通过。
- Windows 高 DPI 下检查了 940×700 小窗口、1220×800 默认窗口和超过 30 项开关的滚动布局；使用示例配置检查界面截图。
- 新增回归测试只写临时用户层；网络测试使用本地模拟服务，没有提交真实模型请求。

## 验证边界

- 开关面板目前反映用户层已有布尔字段和行启用状态，不自动列出 bundle 的全部可选功能。
- 保存不自动重启服务，也不表示某项功能已在运行时执行。MOA 等行为仍取决于 Forge 的配置完整性和启动方式。
- 未验证真实模型、实际微信通道收发或用户正在运行的 Forge 服务；没有为验证重启这些服务。
- 文件变化检查是乐观保护，未对不遵守同一协议的其他写入程序提供跨进程锁。
