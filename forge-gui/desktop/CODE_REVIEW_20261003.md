# Forge 代码与运行完整性审查 · 2026-10-03

## 已修复

| 问题 | 修复与验证 |
| --- | --- |
| GPU 探测、工具命令、联邦调用、检查点 Git、通道进程检查可能创建控制台 | 后台调用显式使用 Windows `CREATE_NO_WINDOW`；真实子进程测试确认 `GetConsoleWindow()` 为零，保留输出捕获与原有功能。 |
| 工作区刷新和 Diff 在 Tk 线程里等待 Git | 桌面操作改为后台读取，主线程只更新控件。每类请求最多一个运行中的任务和一个待处理请求；快速切换时忽略旧结果；关闭控件时取消轮询。独立使用的同步 `refresh()` API 保留。 |
| 端口清理可阻塞界面，并可能误停另一个 Forge | 占用端口的调查改为后台执行。只清理命令行中仓库路径、home 均匹配且父进程已退出的孤儿 Gateway；仍被占用时明确报错。停止或退出会取消尚未完成的启动；异步失败保持重试计数，防止无限重试。 |
| 退出时等待资源监测线程，或任务刚启动时退出 | 窗口先隐藏，再在后台停止监测和清理进程。任务启动线程完成取消检查后才退出，减少进程启动与关窗的竞争。 |
| UI 事件积压使输入迟迟得不到处理 | 每轮事件消费增加 12 ms 时间预算，处理后让出事件循环。 |
| “添加智能体”和现有智能体目录入口引用不存在的方法 | 补齐入口：新增操作打开已有分工预设编辑器；目录信息只显示实际目录，不虚构注册状态。 |
| 分工预设的启用勾选没有被保存，配置保存失败仍提示成功 | 保留复选框变量并保存实际布尔值，编辑时跟踪未保存状态；写入失败显示错误并保留旧文件；异常配置字段补全合法默认值。 |
| 流式读取卡住时停止无效，断流可能被当成完成 | 每个请求独立持有取消信号和 socket；TCP 连接、TLS 握手、响应头、响应体均接入取消。健康检查、分工与集群继承同一停止信号；缺少完成标记的 EOF 和 SSE 错误明确报错。保留默认代理发现和 TLS 验证。 |
| 未闭合工具调用标签被当成完整调用 | 两个文本工具解析入口都忽略未闭合的调用区域，保留完整调用和 JSON 字符串中的标签文字。 |
| Python wheel 只包含顶层 `forge` 包 | setuptools 收集 `forge` 子包。构建 wheel 后在独立目录导入通道模块并读取随包配置，确认不依赖源码目录。 |
| 部分回归测试依赖真实用户配置 | 增加隔离运行器，验收测试使用临时 home、密钥文件和桌面配置；模拟对话仅保存在测试目录。 |
| 取消或失败后恢复的草稿在变量中存在，输入框却空白 | 恢复变量时同步实际 Text 内容，用户编辑时同步发送载荷，避免发送看不到的旧草稿。 |
| 密钥文件是合法 JSON、但结构错误时可能导致启动失败 | 校验对象和文本字段；读取失败不影响界面启动，写入使用严格读取，损坏的原文件不会被空配置覆盖。锁保护同进程的并发更新；临时文件同目录、独立命名并原子替换。 |
| 历史时间戳异常导致侧栏加载失败 | 对非法值、NaN、无限大及系统不支持的日期进行回退，保留可用的对话条目。 |
| 模型快捷编辑在写入失败时先改变内存，或覆盖外部修改 | 在副本上修改，保存前比较磁盘基线，成功后更新内存；保留单独指定的 smallModel。AutoClaw 导入同样使用副本和基线检查，密钥保存失败明确报告部分成功。 |
| 桌面偏好直接覆盖文件，保存失败被当成成功 | 同目录原子写入，失败返回明确结果；目录、收藏和思考强度的提示区分本次已生效与持久化失败。异常收藏数据不再使启动崩溃。 |
| Provider 探测密钥解析与正式请求不同，旧结果写到新选中项 | 复用正式请求的密钥解析，主线程快照配置；回调校验请求代次、Provider 身份及配置，忽略过期结果。 |
| 后台分工读取 Tk 变量，或读取变化中的 Provider 配置 | 主线程快照环境、模型、Provider 和推理强度，后台只处理快照。删除自动插入的虚构 assistant 确认消息，只传实际上下文。 |
| 配置表达式并发求值串用其他请求的上下文 | 用 ContextVar 隔离每次求值，并在 finally 中恢复；双线程屏障回归确认上下文不串。 |
| 异常退出留下半条会话记录，或写失败时出现内存中的虚构事件 | 恢复时只处理未换行的最后记录：保留损坏片段的独立备份后截断；完整但缺换行的记录保留。已完成记录损坏会明确报错。先写入并刷新，再加入内存；失败后重读磁盘再尝试。 |
| fork(keep_last=0) 意外复制全部历史，事件保留字段被内容覆盖 | 零历史分叉为空、负数拒绝；ordinal、type、ts 由事件本身决定，保护日志身份。 |
| 坏索引或一个损坏日志使整个会话索引不可用 | 坏缓存重建；损坏日志单独标记错误，其余会话仍可查看；索引文件原子替换。 |
| Gateway 非法长度、重复长度或 chunked 请求导致处理异常 | 验证 Content-Length 和实际长度，不支持的传输格式返回 400；工具调用体必须是对象。认证拒绝关闭连接，避免未消费的正文被当成下一次请求。 |
| 打包冒烟用启动时间差判断 Gateway 所有权 | 冒烟禁止自动启动 Gateway，仅回收构建 EXE 的新增 PID；移除对其他新 Gateway 的清理，恢复原环境变量。清理构建目录前校验绝对路径。 |
| 旧的函数式测试未被 unittest 自动发现 | 隔离运行器显式收集配置、客户端、集成和工作区函数测试，纳入完整回归。 |

## 结论与边界

已验证的启动、界面操作、配置保存、任务取消和流式处理链路可以正常运行。
慢 Git 与端口调查不会再占住 Tk 线程，快速切换和退出有对应的回归覆盖。
这些结论来自本机与离线测试，未调用付费模型；真实上游响应速度与可用性仍取决于网络和 Provider。
DNS 解析仍由操作系统处理，取消不能强制中断系统解析器；其余连接与读取阶段已加入取消。
一次完整回归中多路停止超过 2 秒的测试预算；随后连续 60 次复测及最终完整回归通过。取消时间会受系统调度影响，不作固定延迟保证。
这次审查不等于零缺陷保证；尚未使用真实付费模型做上线环境验证。
