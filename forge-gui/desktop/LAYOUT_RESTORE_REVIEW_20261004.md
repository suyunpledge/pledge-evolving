# 工具集返回布局恢复修复 · 2026-10-04

## 首次初始化与退出路径比较

首次 `_build_ui()` 创建一个 body，其中 sidebar 先以 `side=left, fill=y` 加入 pack 队列，随后加入 split。center 与工作区 ws_holder 始终属于 split。

进入工具集经 `_show_view()` → `_apply_responsive_layout()` 自动收起侧栏。原返回路径通过 `_set_sidebar_visible(True)` 重新调用 `pack(side=left, fill=y)`，没有指定队列位置。Tk 的 `pack_forget()` 会丢失布局参数和队列位置，再次 pack 默认追加到末尾。

因此首次顺序为 `[sidebar, split]`，旧返回路径成为 `[split, sidebar]`。两者都使用 `side=left`，但 split 先取得窗口左侧空间，sidebar 随后出现在它右侧。sidebar 的对象和 parent 实际没有变化；错误是 pack 排列顺序发生变化。

桌面配置读取仅用于模型收藏、思考级别和仓库路径等设置，没有持久化 sidebar 停靠或 pack 顺序。退出路径也没有重建 body、sidebar、split 或工作区。本次问题属于运行时布局恢复错误。

## 修复

- 初始化时保存 sidebar 的实际 `pack_info()`。
- 收起前保存现有布局参数。
- 展开时复用同一个 sidebar、相同 parent 和原布局参数，并明确指定 `before=self.split`，恢复首次初始化的左侧停靠顺序。
- 工具集退出、其他页面退出、手动切换侧栏和响应式自动恢复统一使用这个恢复路径。
