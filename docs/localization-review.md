# 本轮源码审查与多语言接入

## 基线与范围

基于 `104d35f` / `8bee44b` 的当前源码。审查最新圆角绘制、插件市场入口与操作分发，以及多语言接入对现有交互的影响。圆角绘制与现有插件执行边界保持不变。本轮仅修改源码、翻译资源、测试与打包资源声明，没有构建或复制 EXE。

检查当前项目时没有找到已有的语言模块或语言设置入口，因此在这份源码中增加了显式的显示层本地化。若另有独立多语言分支，需要另行合并，不能据此认为已审查过该分支。

## 用户入口

打开 **配置 → 界面语言**。可选简体中文、繁体中文、英语、日语、韩语、德语、法语、西班牙语、葡萄牙语、俄语。选择立即生效，并保存到现有桌面配置的 `language` 字段。下次启动在创建界面前读取语言，不会先显示中文再重建界面。

第一批翻译目录各含 248 条核心文案，包括导航、聊天空态、输入提示、模型选择、工作区入口、市场状态、权限说明及授权范围。用户对话、输入草稿、文件内容、模型 ID、插件名称与第三方 manifest 内容保持原文；尚未接入的详细提示采用中文回退。未实现自动机器翻译或改变 Agent 回复语言。

## 审查结果与修复

| 问题 | 影响 | 修复 / 验证 |
| --- | --- | --- |
| `_market_action` 的允许列表没有 grant / revoke | 卡片上的能力授权及撤销按钮静默失效 | 先复现两个失败测试，再补齐已有分支的入口；没有改变授权判定 |
| 固定排列的市场筛选行遇到长译文或高 DPI | 生态源 / Codex 按钮被挤掉或越过边界 | 按控件实时请求宽度换行，保留原 parent；验证 10 种语言 × 5 个 DPI 比例 × 最小支持窗口 |
| 语言可能参与类型筛选、作用域或能力 ID 的比较 | 显示语言改变业务筛选结果 | `Message` 保留原始字符串；仅带标记的显示文案在所属 Tk 解释器内渲染，筛选值及权限 ID 保持稳定 |
| 切换语言时重建界面可能丢草稿 / 改变 dock | 编辑内容或工作区布局丢失 | 更新已有文本绑定，不重新构建主界面；回归验证组件树、视图、草稿及配置编辑内容 |
| 配置保存失败却继续显示切换成功 | 重启后语言与界面宣称不一致 | 保存成功后才切换；失败保留原语言并报告错误 |
| 缺失 / 损坏 / 格式不匹配的翻译 | 启动失败或出现格式异常 | 白名单语言代码、JSON 类型与大小检查、占位符一致性验证、原文回退 |
| 多个 Tk 根或销毁控件仍有绑定 | 串语言或访问已销毁 Tcl 控件 | 每个根窗口独立 Translator，弱引用绑定；销毁控件可安全跳过 |
| 打包遗漏翻译资源 | 冻结版缺少语言目录 | spec 声明 i18n 模块与 locales/*.json；本轮没有运行打包 |

## 维护方式

资源在 `forge-gui/locales/<language>.json`，UTF-8；键为稳定的中文原文。主代码显式 `tr(...)` 标记系统文案，使用 `i18n.Label` / `Button` 等控件，或自绘控件的显式文本绑定。不要给用户输入或第三方内容自动套 `tr`。

动态文案采用命名占位符，例如 `tr("当前工作区：{name}", name=repo)`。所有翻译必须保留相同占位符及格式；复杂对象访问和嵌套格式字段不接受。可组合的翻译保持标记，避免用 f-string 或 `str(...)` 提前丢掉绑定。

显示状态可使用 `i18n.StringVar`；用户编辑、类型筛选、scope、model、mode 等业务值使用原有 `tk.StringVar`。翻译文件按语言缓存，切换只更新显示控件，不发网络请求。

运行验证：

```powershell
python forge-gui/run_offline_checks.py test_i18n test_plugin_market_ui
python forge-gui/run_offline_checks.py
```

测试使用临时 Forge home 与桌面配置，不修改真实语言偏好或 API 密钥。

本轮验证：**377 个不同测试用例分批全部通过**。包括既有桌面回归、两个授权 / 撤权入口回归、多语言的 8 项检查，以及 10 种语言 × 5 个 DPI 比例的最小窗口检查。

第一次合并运行在末尾多语言组出现异常耗时，暂停了本轮测试进程；没有修改 Forge 应用进程。随后在相同功能源码上启用 Windows DPI 感知，独立多语言组 8 项全部通过（70.4 秒），并补跑了尚无成功记录的 19 项。按实际成功的测试 ID 合并记录，得到 377/377，未将仅开始执行的用例算作通过。异常耗时原因尚未确定，不能据此宣称已解决所有 Tk 或实际应用的响应性问题。
