# 请求等待与超时恢复修订 · 2026-11-12

审查基线：主仓 `9d1d22a`，保留工作区已有的桌面界面修改。本轮修复模型等待、网关配置传递、流式结束和取消行为，不改模型请求正文或缓存命名空间。

## 问题与生效策略

| 路径 | 原行为 | 当前行为 |
| --- | --- | --- |
| 桌面聊天 | 60 秒先于网关超时 | 默认 600 秒上游等待，客户端另留 60 秒传输余量 |
| 独立规划/复核 | 固定 60 秒 | 复用内核默认 600 秒或 Provider 的明确配置 |
| 桌面子任务 | 默认 30 秒 | 默认 600 秒，保留显式子任务/Provider 限制 |
| 内核直连 | 默认 120 秒 | 默认 600 秒 |
| `requestTimeout` | 平铺导入、桌面启动参数和网关转发存在遗漏；小数被截断 | 全链路传递，支持有限非负秒数，0/空值继承默认 |
| 工具桥 | 部分入口固定 3 秒就报错 | 默认 90 秒；`shell_exec` 显式执行时限再留 30 秒传输余量，调用方显式 HTTP 时限优先 |
| 健康/工具目录查询 | 与生成请求容易混用等待时间 | 健康检查仍为 5 秒，工具目录默认为 10 秒 |

以上均为 socket 无活动等待，不是整个任务的总时限。有持续输出的长任务可继续运行；用户明确配置的较短时限仍被尊重。检查本机默认配置时，18 个启用 Provider 都没有声明非零 `requestTimeout`，没有修改用户配置或凭据。

## 流式结束

- `[DONE]` 和 Anthropic `message_stop` 到达后立即结束读取，不等服务器关闭 TCP 连接。
- OpenAI 全部请求 choice 都收到 `finish_reason` 后，最多再收尾 5 秒以接收 usage；到期或此阶段 socket 超时不再丢弃已完成回复。显式更短的 socket 时限继续生效。
- 正文、思考或工具参数尚未完成时，超时仍是失败；不自动重发流式请求。输出因 `length` / `max_tokens` 截断时，桌面也会阻止该轮工具调用。
- 修正脱敏缓冲区的终帧顺序：正文片段、缓冲尾部、结束标记依次输出；usage 只发一次。一个 choice 结束不会提前释放另一个 choice 的秘密前缀缓冲。
- 收尾窗口之外的统计无法保证获得，缺失统计不编造为完整账单。

## 取消与重试

桌面已有的可取消 HTTP 实现提取至 `forge/http_transport.py`，桌面保留兼容入口。内核主生成、规划、沉思、限流等待和重试退避接入取消信号；取消是不可重试结果，不切换 Provider，也不把 premium 的草稿降级成“成功完成”。

HTTP 408 / 524 纳入内核已有的有界重试策略，401 和请求参数错误保持不可重试。读取错误响应正文再超时，不会丢掉原 HTTP 状态的分类。工具请求超时仍带 run/action ID，由调用方检查执行状态，不自动重复执行写入或命令。
