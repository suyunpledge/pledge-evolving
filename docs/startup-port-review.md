# Forge 启动端口修复（2026-10-06）

## 复现与根因

桌面版网关以代码 1 退出，工作区终端显示
`PermissionError: [WinError 10013]`。
本机 `netsh interface ipv4 show excludedportrange protocol=tcp`
列出的保留范围包含 **8767–8866**，默认端口 **8799** 位于其中。
TCP connect 检测只能判断是否已有监听者，不能证明系统允许绑定。

原有日志只记录进程创建成功，且在进程创建后清零失败计数。
因此每隔约 17 秒重复退出、重启时，60 秒内 5 次的限流始终不会触发。
此外，端口清理 / CreateProcess 阶段没有总超时，状态始终显示检查端口。

## 修复边界

- 后台检查端口绑定。仅 Windows 10013 权限拒绝允许改用系统分配的
  本机端口；已有监听者仍经过原有所有权检查，不自动覆盖或改连服务。
- 启动阶段回调同步子进程参数、GUI 端口、网关 URL 和客户端 URL。
  网关就绪后保存端口，后续启动复用。最终绑定仍由网关执行；检查与
  子进程绑定之间若发生竞争，按照明确的失败流程处理。
- 准备阶段 30 秒超时后恢复操作并暂停自动重试，避免挂起的后台步骤
  引发更多并行启动。Python 线程无法强行终止 CreateProcess；迟到的
  子进程会被清理，旧回调无法覆盖新启动，关闭窗口会收集待交接进程。
- 就绪检查成功才清零启动失败计数。就绪前退出最多自动尝试 6 次。
  健康检查超时的进程清理在后台执行，保持 Tk 响应。
- 保持原有本机监听、Provider、Policy / workspace 设置；没有修改
  系统保留端口、防火墙、安全权限或 EXE。

## 验证

新增 `forge-gui/test_gateway_startup_lifecycle.py`，覆盖系统保留端口、
占用端口、地址同步、准备超时、取消、旧回调、就绪计数、慢速崩溃上限、
非主线程清理与关闭时待交接进程清理。先复现失败后再修复。

真实网关使用临时 home 和不可访问的测试上游验证：自动选择可用端口，
约 1.5 秒就绪，GUI / 客户端地址一致，停止后诊断子进程确认退出。
用户真实配置的源码入口也已启动并记录就绪。本次不向上游发送对话。
本机实际服务 `/v1/models` 返回 HTTP 200，可用端口已保存。
10 项新增测试与 111 项相关旧回归通过（120 项批次，加最终新增测试批次）。

现有桌面 EXE 内含旧 GUI 代码，需要重新打包才能包含源码修复。
当前提供桌面「Forge（源码修复版）」入口，直接运行 Python 3.12 的
`pythonw.exe` 与当前 GUI 源码，无需生成新 EXE。
