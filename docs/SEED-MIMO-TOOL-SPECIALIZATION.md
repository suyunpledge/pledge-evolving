# Seed / MiMo 工具调用专项实测

2026-11-08，使用本机已有配置的 `doubao-seed-evolving` 和 `mimo-v2.6-flash` API。发送的是临时账单项目，不发送真实项目代码或本机密钥。没有更改用户的全局模型、思考模式或权限配置。

## 任务与实际调用链

第一轮修复两个有缺陷的账单模块：Decimal 金额、ROUND_HALF_UP、非法金额及数量校验、退款、取消订单、逐行舍入、币种排序和输入不可变性，共 11 项测试。第二轮追加可选币种过滤参数，保持原行为兼容，共 14 项测试。要求先用工具复现失败，再修改源码，最后通过测试。

每轮重新创建 Agent，复用同一 home 和工作区；执行经过路由器、原生工具消息、ActionExecutor、策略、文件版本防护、工具结果留存、会话存储及环境探针。规划设为 low，压缩预算故意收紧到 12,000 字符、保留尾部 6 条消息，最多 18 步。这个预算用于暴露压缩问题，不代表生产默认值。模型实际调用读文件、搜索、写入、编辑、变更检查和结果分页工具。

`run_checks` 是宿主绑定的固定 Python unittest 命令，不接受模型命令参数。它在临时工作区运行，环境不继承 Forge 密钥。策略只为这个固定执行器显式放行；受保护执行器对任意 `shell_exec` 的禁止保持有效。固定执行器的工具成功表示命令已执行，测试结果由 passed/exit_code 表示；独立环境探针读取实际测试退出状态，不能把“执行成功”误当作“测试通过”。

测试和 SPEC 在每轮执行前固定哈希，检查时若发生修改就验收失败。导出的模型源码保存在各报告对应的 `-sources` 目录。验收脚本还会核对工作区变化范围、写入前是否实际复现失败，并保存脚本及主要运行时文件哈希；这部分增强在本次已启动的 API 批次之后加入，早期报告不含这些新字段，另以离线审计核对可观察证据。

## 根据反馈实现的修改

- Seed 基线两次请求 `artifact_read(limit=4000)`，被 3000 上限拒绝。现在对正整数超限请求返回有界页面，同时标明 requested_limit、effective_limit、limit_capped 和真实 next_offset；负数、布尔、非整数及策略拒绝仍返回失败。权限判断先于分页处理。
- 长命令失败输出现在提供退出码、非零状态及失败要点，并保留完整原文句柄。已执行的失败动作可以使用宿主提供的结构化视图，动作仍保持 failed/completed，不能被展示层改成成功。
- 内置命令处理器不再提前丢掉输出头部，仅保留最后 4000 字符。完整输出交给统一留存层处理；独立子进程回归测试验证首行失败名称和 7000 多字符原文能逐页完整恢复。
- 结果提示改为“需要准确细节时才检索”，避免把分页检索变成固定必做步骤。没有根据几次模型失误增加猜测路径、模糊工具名匹配或截断 JSON 补全规则；本次没有观察到需要这类修复的原生协议错误。

失败摘要是启发式的有界提示，不是完整错误解析器；原文仍可搜索、分页回读。报错中重复读取、误用根目录相对路径以及网络中断也保存在报告中，没有转换成工具成功或模型通过。

Seed 摘要版首轮输入 33,471、输出 2,867，11 个工具动作，通过测试及宿主环境探针；基线首轮 30 个工具动作、两次分页参数错误、7 次压缩，仍未修复。改动缓解了这个具体失败模式。首个失败日志原始 JSON 为 10,419 字符，摘要版给 Seed 904 字符、最终版给 MiMo 912 字符，并留存原始 JSON。不是删除模型可能需要的细节。

MiMo 最终版两轮均实际先运行失败测试、写入源码、再运行成功测试，19 个工具动作、3 次压缩；第二轮记录磁盘会话前缀复用事件。缓存统计为 55,104 / 69,904，所有 18 条响应均有缓存数据。基线只有 12 条响应有缓存数据，为 33,152 / 48,975；另两条成功响应有输入 usage 但没有缓存统计，三次传输失败没有 usage。

**没有得到整体 token 节省结论。** MiMo 最终版输出低于基线，但输入增长，总 token 高出 27.35%。关闭思考也通过，却出现测试成功后的重复读取/检查，输入更高；因此不自动关闭思考。摘要版初稿的提示要求先检索原文，MiMo 首轮花了更多步骤阅读，已改成按需检索；最终版通过且开销低于初稿，但这是顺序单样本，服务端前缀已变热、网络情况不同，不能据此宣称普遍提升或严格的因果节省率。Seed 第二轮尚未验证通过，也不把第一轮通过写成整组成功。

7 组共 140 次 HTTP 尝试、119 条有效 usage：观测输入 477,559、输出 30,022，合计 507,581 token。21 次失败没有 usage，账单未知；另外 5 条成功响应缺少缓存统计。没有继续提高重试次数、全局关闭思考或更换端点来掩盖失败。

`reports/tool-specialization-audit.py` 将 12 个阶段导出的模型源码复制到新目录，重新写入原始宿主测试并实际执行；通过/失败均与各自报告一致。审计还核对通过阶段在编辑前确实运行了失败测试、观察到的编辑路径符合要求、第二轮 pricing.py 不变。早期批次没有完整工作区快照，不能据此证明不存在所有其他文件变化；已在后续验收脚本补齐快照核对。

核心测试 497 项通过（2 项跳过）；工具结果、留存及编码工具定向测试 47 项通过；执行反馈、网关、客户端和运行时回归 97 项通过。这些测试集合有重叠，不相加宣称覆盖数量。预算检查通过：156 文件、48,541 行。

```powershell
python scripts/verify_tool_challenge.py --live --vendor seed --feedback-views --output reports/seed-tool-new.json
python scripts/verify_tool_challenge.py --live --vendor mimo --feedback-views --output reports/mimo-tool-new.json
python scripts/verify_tool_challenge.py --live --vendor mimo --feedback-views --thinking off --output reports/mimo-tool-off-new.json
```

输出路径必须不存在，`--live` 必填；默认总请求上限 48，每次请求最多重试一次。省略 `--feedback-views` 可以保留基线固定执行器的原始 JSON 结果格式，但仍使用当前运行时，不能重建修改前的分页拒绝行为。`--thinking off` 只影响本次脚本提供者实例。

本轮增量补丁和文件哈希清单为 `reports/tool-specialization.patch`、`reports/tool-specialization-files.json`，只收录本轮改动，不替换工作区已有修改。
