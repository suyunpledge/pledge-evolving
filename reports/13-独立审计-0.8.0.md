## Executive Summary

Agent-forge is a well-architected AI-agent framework with unusually strong security posture for its class. The codebase shows evidence of iterative hardening (H6-H19 revisions, DeepSeek receipts, WorkBuddy patches). However, several concrete issues remain — ranging from a confirmed sandbox escape vector to architectural duplication between the forge and evolution modules.

## Top 10 Issues

### 1. 🔴 CRITICAL: `eval()` in config expression evaluator — sandbox escape

**File:** `forge/config.py`, line 129  
**Code:**
```python
return eval(compile(tree, "<config>", "eval"), {"__builtins__": {}}, namespace)
```

**Problem:** The AST whitelist blocks `Attribute` nodes, but `eval()` with `__builtins__={}` is not a true sandbox in CPython. Known bypasses exist via `__subclasses__` traversal on built-in types (e.g., `(1).__class__.__class__.__bases__[0].__subclasses__()`) — though the `Attribute` node block should catch this specific chain, the defense is one AST node type away from failure. A single missed node type (e.g., `ast.NamedExpr` is allowed) could enable code execution.

**Fix:** Replace `eval()` with a pure-function evaluator that only calls whitelisted functions from `_CALL_IMPLEMENTATIONS`:
```python
def _eval_expr(expr: str, ctx: dict[str, Any]) -> Any:
    tree = ast.parse(expr, mode="eval")
    # ... existing validation ...
    # Replace eval() with tree-walking interpreter:
    return _eval_node(tree.body, namespace)

def _eval_node(node, ns):
    if isinstance(node, ast.Constant): return node.value
    if isinstance(node, ast.Name): return ns[node.id]
    if isinstance(node, ast.Call):
        func = _eval_node(node.func, ns)
        args = [_eval_node(a, ns) for a in node.args]
        return func(*args)
    # ... etc for BinOp, Compare, IfExp, BoolOp ...
    raise ConfigError(f"unsupported expression node: {type(node).__name__}")
```

**Backward compatibility:** All existing `$expr` expressions use only the whitelisted operations; the new evaluator produces identical results.

### 2. 🔴 CRITICAL: `shell_exec` uses `shell=True` — command injection surface

**File:** `forge/tools.py`, line 254  
**Code:**
```python
proc = subprocess.run(command, shell=True, ...)
```

**Problem:** The `DEFAULT_DENY_PATTERNS` and `DEFAULT_FORBIDDEN_PROGRAMS` blacklists are regex-based. Regex blacklists are inherently incomplete — new escape vectors appear regularly (e.g., `pwsh`, `bash -c`, encoded commands via `certutil`, `mshta`, `rundll32`). The `shell=True` means the OS shell interprets the command, adding another layer of injection surface.

**Fix (two layers):**
1. Add `pwsh`, `bash`, `cmd` (when used as wrapper) to `DEFAULT_FORBIDDEN_PROGRAMS`
2. For non-interactive mode, default to `shell=False` with `shlex.split`:
```python
if ctx.policy.non_interactive:
    import shlex
    proc = subprocess.run(shlex.split(command), shell=False, ...)
else:
    proc = subprocess.run(command, shell=True, ...)
```

**Backward compatibility:** Interactive mode unchanged; non-interactive gains stricter parsing.

### 3. 🟡 HIGH: Memory store has no file-level locking — race condition

**File:** `forge/memory.py`, lines 89-96 (`save()` method)  
**Code:**
```python
tmp = self.path.with_suffix(self.path.suffix + ".tmp")
tmp.write_text("\n".join(lines), encoding="utf-8")
tmp.replace(self.path)  # atomic swap
```

**Problem:** The atomic swap prevents half-written files, but two concurrent `remember()` calls will still race: both read the same state, both compute their additions, and the second `replace()` overwrites the first's changes. The `entries` list in memory is also not thread-safe.

**Fix:** Add a file lock around the read-modify-write cycle:
```python
import threading

class MemoryStore:
    _lock = threading.Lock()

    def remember(self, text, **kw):
        with self._lock:
            # ... existing dedup check ...
            self.entries.append(entry)
            self.save()
            return entry
```

For multi-process safety, use `msvcrt.locking` (Windows) or `fcntl.flock` (Unix) on a `.lock` sidecar file.

**Backward compatibility:** Fully compatible; adds safety without changing behavior.

### 4. 🟡 HIGH: Evolution engine can write to arbitrary file paths

**File:** `forge/evolution.py`, lines 239-249 (`apply()` method)  
**Code:**
```python
target = Path(candidate.target)
# ... no sandbox check ...
target.write_text(existing + block + candidate.content + "\n", encoding="utf-8")
```

**Problem:** The `candidate.target` is a filesystem path that the evolution engine writes to. There is no sandbox boundary check — a candidate could target `~/.bashrc`, `/etc/crontab`, or any path the process can reach. The `LONG_TERM_MARKERS` check only gates *approval*, not the path itself. A `force=True` call bypasses all checks.

**Fix:** Add sandbox-aware path validation in `apply()`:
```python
def apply(self, candidate_id, *, by="", force=False):
    candidate = self._require(candidate_id)
    target = Path(candidate.target)
    # Enforce workspace boundary for writes
    if self._workspace and not str(target.resolve()).startswith(str(self._workspace.resolve())):
        raise PermissionError(f"target {target} escapes workspace boundary")
    # ... rest of existing logic ...
```

**Backward compatibility:** Adds a safety check; existing valid candidates (within workspace) are unaffected.

### 5. 🟡 HIGH: Forge ↔ Evolution module duplication

**Duplication identified:**

|---------|---------------------|------------------------------|---------------------------|

**Specific overlaps:**

3. **Checkpoint integration** — `EvolutionEngine.apply()` snapshots before writes; `loop.py` snapshots before tool calls. Both call `self.checkpoints.snapshot()` with the same pattern.

**Refactoring plan:** See Section 4 below.

### 6. 🟡 HIGH: `_boot_ctx` leaks full `os.environ` into config evaluation

**File:** `forge/config.py`, line 167  
**Code:**
```python
return ctx if ctx is not None else {"env": dict(os.environ)}
```

**Problem:** Every config expression evaluation gets the full process environment. A config layer (which is attacker-reachable — plugins/overlays can ship one) can use `$expr` to read any environment variable, including secrets:
```json
{"$expr": "get('env.AWS_SECRET_ACCESS_KEY')"}
```

**Fix:** Whitelist the env keys that config expressions may access:
```python
_ENV_WHITELIST = frozenset({"FORGE_API_KEY", "FORGE_BASE_URL", "HOME", "PATH", ...})

def _boot_ctx(ctx):
    if ctx is not None:
        return ctx
    env = {k: v for k, v in os.environ.items() if k in _ENV_WHITELIST}
    return {"env": env}
```

**Backward compatibility:** Existing bundles only reference `env.FORGE_*` keys. Unknown env lookups return `""` (the default) instead of the real value.

### 7. 🟡 MEDIUM: Gateway has no authentication — open to local network

**File:** `forge/gateway.py`, lines 186-193  
**Code:**
```python
server = ThreadingHTTPServer(("127.0.0.1", cfg.port), build_handler(cfg))
```

**Problem:** While bound to `127.0.0.1` (good), there is no token/API-key authentication on the gateway itself. Any local process can send requests. In a shared-machine scenario (or if the bind address is changed to `0.0.0.0` for remote access), this becomes an open proxy to the upstream model API.

**Fix:** Add a simple bearer token check:
```python
def do_POST(self):
    if cfg.gateway_token:
        auth = self.headers.get("Authorization", "")
        if auth != f"Bearer {cfg.gateway_token}":
            self._json(401, {"error": "unauthorized"})
            return
    self._proxy(self._read_body())
```

**Backward compatibility:** When `gateway_token` is empty/None, behavior is unchanged.

### 8. 🟡 MEDIUM: `sanitise_child_output` regex is incomplete

**File:** `forge/loop.py`, lines 39-45  
**Problem:** The `INJECTION_RE` regex covers common injection patterns but misses:
- HTML entity-encoded tags: `&lt;system&gt;`
- URL-encoded forms: `%3Csystem%3E`
- Markdown code blocks containing directives
- Zero-width characters interspersed in tags
- Backtick-fenced blocks with role prefixes

The previous audit (report 08) already flagged this; the regex was expanded but the fundamental approach (blocklist regex) remains fragile.

**Fix:** Switch from blocklist to allowlist — strip everything that isn't plain prose:
```python
def sanitise_child_output(text: str) -> str:
    """Strip anything that could be a directive. Allowlist approach."""
    # Remove all XML/HTML-like tags
    cleaned = re.sub(r'<[^>]+>', '[redacted]', text or "")
    # Remove role prefixes at line start
    cleaned = re.sub(r'^\s*(SYSTEM|ASSISTANT|USER|DEVELOPER)\s*[:：]', '', cleaned, flags=re.M)
    # Remove bracket directives
    cleaned = re.sub(r'\[/?INST\]|<<\s*/?SYS\s*>>', '[redacted]', cleaned, flags=re.I)
    return cleaned.strip()
```

**Backward compatibility:** More aggressive filtering; legitimate content rarely contains XML tags or role prefixes.

### 10. 🟡 MEDIUM: `Session._write_line` and `Session.append` dual write paths

**File:** `forge/session.py`, lines 68-78  
**Code:**
```python
def _write_line(self, payload):
    with self.path.open("a", encoding="utf-8") as fh:  # opens a NEW handle
        fh.write(json.dumps(payload, ensure_ascii=False) + "\n")

def append(self, etype, **data):
    # ... uses self._fh ...
    self._fh.write(event.to_line() + "\n")
```

**Problem:** `_write_line` opens a new file handle each time, while `append` uses the persistent `self._fh`. If `_write_line` is called while `self._fh` is open (e.g., during `open()` when writing the meta line), both handles write to the same file. On Windows, this can cause interleaved writes or locked-file errors.

**Fix:** Route all writes through `self._fh`:
```python
def _write_line(self, payload):
    if self._fh is None:
        self._fh = self.path.open("a", encoding="utf-8")
    self._fh.write(json.dumps(payload, ensure_ascii=False) + "\n")
    self._fh.flush()
```

**Backward compatibility:** Fully compatible; same output, single write channel.

## 3. Forge ↔ Evolution Module Duplication Analysis

### Overlapping Responsibilities

| Area | `forge/evolution.py` | `forge/loop.py` + seats |
|------|---------------------|------------------------|
| **Lifecycle state machine** | `pending → approved → applied → rejected/quarantined/stale` | Seats have no state machine; metabolise is fire-and-forget |
| **Archiving** | `curate()` archives stale candidates after 7 days | `curator` seat archives memory entries after 30/90 days |
| **Ledger** | `Ledger` (JSONL, append-only, `seq/ts/action/candidate_id`) | `CostLedger` (JSONL, append-only, `model/tokens/cost/at`) |
| **Checkpoint** | `apply()` → `checkpoints.snapshot()` | `run()` → `checkpoints.snapshot()` before write tools |
| **Version tracking** | `bump_version()` writes version snapshots | No version tracking in loop |

### Key Insight

The evolution module is a **self-contained state machine** with its own persistence, while the loop's metabolism is a **hook-based consultation** with no persistent state of its own. They are complementary, not truly duplicated — but they share patterns (append-only logs, checkpoint-before-write, archive-never-delete) that could be extracted into shared primitives.

## 4. Refactoring Plan

### Phase 1: Extract Shared Primitives (Low Risk, High Value)

1. **`forge/journal.py`** — Unified append-only JSONL journal
   - Merge `Ledger` and `CostLedger` into one class with typed entries
   - Both evolution and pricing become consumers, not implementors
   - Backward compatible: existing `.jsonl` files are read by the new journal

2. **`forge/safety.py`** — Centralized sandbox enforcement
   - Move `allows_write`, `_command_denied`, and the new evolution path check into one module
   - Evolution's `apply()` calls the same sandbox as policy's `evaluate()`
   - Eliminates the gap where evolution writes bypass the policy sandbox

3. **`forge/archive.py`** — Shared archive-never-delete primitive
   - `MemoryStore.curate()` and `EvolutionEngine.curate()` both implement the same pattern
   - Extract: `archive_entries(entries, predicate, ledger)` → returns archived count
   - Both modules call this instead of rolling their own

### Phase 2: Harden the Expression Evaluator (Medium Risk)

4. **Replace `eval()` in `config.py`** with a tree-walking interpreter
   - Pure function, no `eval/exec/compile`
   - Same whitelist, same results, zero sandbox escape surface
   - Self-test verifies all existing expressions still resolve

5. **Whitelist env keys in `_boot_ctx`**
   - Default whitelist: `FORGE_*`, `HOME`, `PATH`, `USER`, `SHELL`
   - Config can declare additional keys via a manifest row

### Phase 3: Consolidate Write Safety (Low Risk)

6. **Evolution sandbox integration**
   - `EvolutionEngine.__init__` accepts a `workspace: Path` parameter
   - `apply()` validates `target` against workspace before writing
   - Existing behavior: if no workspace is passed, no check (backward compat)

7. **Session write unification**
   - Remove `_write_line`; all writes go through `append()`
   - Add `append_meta()` for the session_meta line (ordinal=0)

### Phase 4: Gateway Hardening (Low Risk)

8. **Optional gateway authentication**
   - `GatewayConfig` gains `gateway_token: str = ""`
   - Empty = no auth (backward compat); set = bearer check
   - TOOLS.md documents the recommendation

### Phase 5: Test Coverage Gaps

9. **Add tests for:**
   - Concurrent `MemoryStore.remember()` (thread safety)
   - `EvolutionEngine.apply()` with out-of-workspace targets
   - Config expressions that attempt env exfiltration
   - `sanitise_child_output` with HTML entities, zero-width chars, code fences

## Conclusion

The codebase is defensively written with clear evidence of iterative security hardening. The most urgent fix is the `eval()` replacement (Issue 1), followed by the evolution sandbox gap (Issue 4). The forge/evolution duplication is an architectural concern best addressed through extracted primitives rather than merging the modules — they serve different purposes and should remain separate.

**Risk summary:**
- 🔴 2 critical issues (eval sandbox, shell=True)
- 🟡 8 high/medium issues (race conditions, auth gaps, duplication)
- ✅ No leaked API keys in current code
- ✅ No hardcoded credentials
- ✅ Strong permission model (deny-wins, child ceiling clamping)
