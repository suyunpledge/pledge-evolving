# Forge GUI/UX 改造交付记录（2026-10-11）

## 范围与架构

实际桌面栈是 Python Tkinter/ttk。先审查主窗口、消息渲染、输入区、Agent/API 表单、插件市场、DesktopFeatures、工作区和现有测试，再沿用 `gui_theme.py` / `ui_icons.py` 的组件系统实施。设计规范见 [forge-workbench-design.md](forge-workbench-design.md)。没有引入第三方运行时依赖、没有新建业务页面、没有打包或生成 EXE。

本轮按共享设计系统 → 聊天/输入/工作区 → Agent/API → 其他页面 → 全量回归推进，每阶段有相关测试与修复记录。此前已存在的控件反馈修改继续保留。

## 设计系统

- 主背景 #11151C，侧栏 #171C25，卡片 #1D2430，输入 #151B25；正文 #EDF1F7，次要文字 #ABB5C5。
- 蓝色交互强调、低饱和成功/警告/错误状态；白字主按钮、正文和焦点环有对比度测试。主品牌图标保留。
- 聊天/输入内容列最大 1040、普通表单最大 800 个 96-DPI 布局单位；统一实时宽度计算、DPI 换算、居中及收缩。
- 复用 Button/IconButton、pill/glyph、RoundedCard、badge、Tooltip、Dialog、Tk/ttk 编辑及选择控件。统一 Hover、Pressed、Focus、Disabled，不增加装饰动画或阴影。
- 不让所有区域都具有相同边框重量：助手正文无大气泡，分组无重描边，子 Agent 编辑卡与输入边界保留细线。

## 布局、裁切与卡顿修复

1. 聊天宽度由实际 viewport、DPI gutter 和头像区域共同决定。助手正文不再用文本长度猜测气泡宽度，嵌套内容遵循实际分配宽度；原有 Text 实测高度、字体回退和 Emoji 内嵌图片处理保留。
   普通用户正文取消 Tk Label 自带 border/padding，避免已经按气泡内宽计算的 wraplength 再多占几像素；保留实际宽度验收，未通过增加额外空白解决。
2. 长路径/代码/表格在自身编辑控件内滚动，不扩大整个页面；代码和表格复制保留源内容。
3. 输入焦点事件使用追加绑定，避免主题反馈覆盖 IME/caret 处理；模型弹层关闭和焦点恢复路径未改变。
4. 请求失败不再同时插入助手错误说明和红色卡片。单卡片保存完整脱敏详情，提供真实模型切换和“编辑后重试”，终端记录保留，不自动产生付费重试。
5. 隐藏/展开右侧面板只操作既有分栏，不重新创建或重排侧栏；当前恢复是进程内布局状态。
6. 发现 Tk 主线程首次解码整张 1,382 Emoji 图集的明显阻塞，改成构建时无损分页、每页最多 256 图块，并沿用解释器内缓存。一次相同的独立 Tk 加载测量：32px Emoji 从 22.797 秒降至 0.687 秒；这不是完整应用启动时间或各机器性能保证。
7. 200% 缩放、940×700 窗口下市场可用高度只有约 387px，固定工具栏把生态筛选/列表压到 1px；改为复用已有 ScrollArea 滚动整页，返回入口保持固定。测试增加将筛选按钮滚入实际视口的坐标检查。
8. 图片预览明确指定 PhotoImage 的所属窗口，修复多个 Tk 解释器存在时 `image ... doesn't exist`。先新增失败回归，再做单行修复。文本 diff 测试改为选择文本文件，避免把本轮新增 PNG 误当文本 diff 样本。
9. 最后一段测试虽断言通过，仍捕获关闭文件标签后 `_clear_highlight` 的孤儿 Tcl 回调。新增失败回归，补齐销毁时取消高亮计时器；区域提示计时器改由跟踪它的面板持有，避免子区域先销毁导致取消失败。验证不取消其他组件的计时器。

## 已批准的最小安全修复

现有 Gateway 清理回归在 HEAD 基线同样失败：放宽分支可能清理父进程仍存活、或脚本路径不匹配但同 home 的 Gateway。用户批准删除放宽分支。现在仅清理脚本绝对路径及 home 都匹配、父进程确认不存活的孤儿进程；未知父进程状态不清理。协议、模型路由不变。扩展所有权测试覆盖正常匹配、父进程存活、错误脚本目录和错误 home。

## 验证结果

全量离线回归执行了 532 项，用时 2297.789 秒。首轮结果为 76 个失败记录（包含 70 个导航子用例）、1 个错误、1 个按环境跳过。失败集中于 7 个测试方法，另有 1 个图片预览错误；已按下列根因处理，复测结果将在完成后写入。没有将这轮全量结果宣称为一次全绿。

- 装饰图元数量、任务页自动隐藏侧栏：旧视觉契约，与 HEAD 现有界面不符；更新为现有简洁图形及稳定侧栏契约。
- 普通用户正文 Tk Label 的默认 border/padding 额外占宽：明确设为零，保留气泡本身的内边距；原请求宽度、实际边界和高度断言保留，并验证完整文本。
- 市场高度耗尽及图片解释器问题：修复 GUI 实现，保持可见/可达验收要求。
- 原生插件隔离测试使用 250ms 人工加载预算：诊断中健康插件和恶意插件都被正确终止；1s 时恶意 30s sleep 被终止、健康插件正常加载。仅将测试预算设为 1s、外部守卫 6s，并加入报告诊断；生产 LOAD_TIMEOUT/执行超时/隔离逻辑未变。
- 唯一跳过项是须 `FORGE_NET_TESTS=1` 的真实网络市场冒烟。

复测过程中还核对了单字气泡：15px 正文加左右各 15px padding，实际 45px，不存在空白撑宽。旧“正文必须占气泡 40%”断言不适用于该情况，改为核对实际 padding 差值，并继续检查正文请求宽度没有被压缩。长消息原宽度断言保持。

一个开启定时 faulthandler 栈采集的长复测批次在 Windows 原生层以 `0xC0000005` 退出，未作为通过结果。没有定位并证明该原生异常的原因；已保留诊断并关闭该临时采集方式，以新进程分段复测。实际生产启动没有加入 faulthandler 或新诊断线程。

最终分段复测：

- 聊天组件、完整导航模块、旧装饰/侧栏/长消息失败用例、插件卡死隔离：**32 项全部通过，470.136 秒**（`.codex-workbench-final-navigation.log`）。
- 市场、响应性、多语言、工作区及新增工作台：**58 项断言全部通过，797.537 秒**（`.codex-workbench-final-market.log`）。同时发现高亮孤儿回调日志，已修复并补回归。
- 高亮/区域提示销毁清理及全部工作区用例：**7 项全部通过，65.862 秒**（`.codex-workbench-final-cleanup.log`），没有再出现该孤儿回调日志。批次间有重复用例，不将数量相加作为独立测试数。

首轮全量中失败的测试方法和图片预览错误均在修复后的分段复测中通过；最后源码没有再重跑一次完整 532 项单进程长批次。编译、i18n 收口、diff 格式和 Emoji 像素一致性检查均通过。无新 EXE、安装包或第三方运行时依赖；未改生产插件超时和权限/审批边界。

阶段验证包括：设计/状态 13 项、聊天/图标 28 项、最终 UI/本地化 27 项、Gateway 所有权 2 项通过；这些批次存在重叠，不能相加为独立用例数。Agent/路由相关阶段唯一失败是已经确认并获准修复的基线 Gateway 问题。

编译检查、6 个 GUI 文件的 i18n 收口检查和 `git diff --check` 通过。18 个 Emoji 分页 PNG 已逐像素与原图对应区域比较，全部相同；没有修改 Emoji 本身。旧装饰回归还要求至少 100 个星点图元，与 HEAD 已采用的 25 图元 Forge 主视觉不符；本轮仅调整该测试为当前切面、轨道、节点和边界契约，没有重画装饰组件。

旧导航回归要求进入任何页面都隐藏侧栏，与此前“任务模式侧栏可用”的实现不符。改为在响应式布局稳定后观察进入前状态，并验证切页保持侧栏可见性、parent 和 pack 顺序；原返回按钮、图标、位置、返回草稿及完整布局快照检查保留。

覆盖真实 Tk 的五档 scaling（100/125/150/175/200%）、十种语言、窗口宽度、聊天换行/高度、模型焦点、导航恢复、配置保存。Tk scaling 测试不等同于逐档改变 Windows 系统显示缩放。

## 保留与限制

Agent 调度、模型路由、Gateway 协议、工具权限、沙箱、插件执行、连接器执行、Secret 边界、配置格式和审批流程保持原实现。回归使用临时配置及离线服务，没有真实厂商付费请求。

原生 UI 观察工具报错 `failed to write kernel assets: 系统找不到指定的路径。 (os error 3)`。实际 Tk 窗口已通过程序化布局和交互测试，但本轮没有完成截图/人眼视觉验收，不能据此宣称所有实际显示环境绝无裁切。

前述诊断长批次的原生异常根因尚未确认，后续关闭定时栈采集的分段复测正常完成；这不等于已经证明实际应用在所有 Windows 环境中绝不会出现原生异常。

后续可选：原生观察工具恢复后检查真实窗口截图及 Windows 系统 DPI；如需要，另行将面板宽度接入现有桌面配置以跨重启保留。目前不修改配置持久化协议。
