# MiMo 绘制 SVG 的端到端耗时

Windows 桌面源码启动器加载 Qt，重启托管网关。沿用[上一轮的任务与模型配置](./README.md)，在 Work 模式、沙箱权限和建模设计师角色下，连续三次发送原句「用 SVG 动画画一个自行车骑鹈鹕」。每次新建会话，使用独立空目录。三张图均由模型当场生成。

原始记录在两次工具检索结束后，单次写文件请求先花 196.89 秒输出思考流，再花 53.91 秒输出工具参数。此次调整仅对默认思考档下、具备写文件权限的简单新 SVG 绘制生效。桌面提供直接写 SVG 的指引，并向支持此开关的小米原生 MiMo 路由发送关闭深度思考的参数。第一次试改节省了时间，但一幅图颠倒了主客关系。随后补充了按原句安排构图的指引，表中三轮均使用修订后的代码。

最终三轮平均 48.06 秒、3,272 输出 token，相较单次历史基线分别下降 83.2% 和 80.9%。生成 SVG 参数成为主要耗时，占每轮约 70% 至 78%。各阶段读取桌面流事件之间的墙钟时间，包含上游生成及网络传输；网关工具计时取同一 action 的开始和完成事件。原子写入计时已包含在网关执行时间内。

## 请求、写入与播放

- 重新打开模型配置，确认上下文和最大输出回显 1,048,576 和 131,072。六个 HTTP 请求均发往小米 Token Plan 的 `/v1/chat/completions`，模型为 `mimo-v2.6-pro`。逐个核对网关本地上下文预算、出站 `max_completion_tokens=131072`、`thinking.type=disabled` 及 HTTP 200。上游各次均报告 0 个推理 token。
- 三轮各有一条成功写入回执、一次实际原子替换和一个独立 SVG 文件。文件分别为 6,549、9,135、5,499 字节，SHA-256 各不相同。三轮均用两次模型请求完成，第二次负责给出最终回复。
- 使用 Edge 158 打开各自的原始文件，核对自行车位于鹈鹕上方。正常播放时，三轮分别观察到 27,578、7,018、7,176 个变化像素。另固定动画时间在 0.15 秒和 0.94 秒截取两帧，分别有 25,231、8,819、6,182 个变化像素。检测阈值为像素亮度差至少 2。
