## 1. 已确认缺陷清单

按严重度排序。每项含触发条件 / 实际结果 / 预期结果 / 证据。

### 🔴 QA-01 · 演化审批闸门可被 `force=True` 整体绕过 — P0

- **触发条件**：`EvolutionEngine.apply(candidate_id, force=True)`，候选为需要审批的类型（memory / skill / config / prompt，或 risk≠low）。
- **实际结果**：未经任何审批即写入目标文件。对照实验中，不传 `force` 时正确抛出 `PermissionError`，传 `force=True` 后 `applied=True`。
- **预期结果**：`force` 只能绕过"证据不足被隔离"这类软条件，**不得绕过人工审批**；或 `force` 仅限 human 上下文调用。
- **证据**：`forge/evolution.py:413-417`（`if candidate.requires_approval and ... and not force`）；复现探针 `qa_regression/probe_defects.py::d2_force_bypasses_approval`，实测输出
  `kind=memory risk=medium requires_approval=True; unforced blocked=True; force=True applied=True`。
- **二次验证**：✅ 已复跑确认。

### 🔴 QA-02 · `approve(by=...)` 无身份校验，Agent 可自批 — P0

- **触发条件**：`EvolutionEngine.approve(candidate_id, by="agent:self")`。
- **实际结果**：接受任意字符串身份，候选转为 `approved`，`decision_by='agent:self'`。
- **预期结果**：审批者身份必须是可验证的宿主/人类主体；`by` 不应是可自由声明的字符串。
- **证据**：`forge/evolution.py:378-386`；探针 `d2_approve_has_no_identity_check` 输出 `approve(by='agent:self') accepted=True`。
- **二次验证**：✅ 已复跑确认。
- **缓解事实**：当前 `EvolutionEngine` 未被注册为 Agent 工具（仅 `cli.py:661-696` 与 selftest 使用），因此**暂无活跃利用路径**；但 API 层闸门是失效的，一旦接上工具面即成真实提权通道。

### 🟠 QA-03 · Agent 写入的长期记忆无需审批即刻生效 — P1

- **触发条件**：`MemoryStore.remember(text, kind="feedback", source="agent")`。
- **实际结果**：重新加载后立即出现在 `context_slice()`（即注入 prompt 的上下文）。
- **预期结果**：`source="agent"` 的条目应经审批/固化后才进入生效上下文。
- **证据**：`forge/memory.py:171-181`（`recall` 不区分 source）、`183`（`context_slice` 直接注入）；`forge/knowledge.py:52` 默认 `source="agent"`、`66-87` 检索同样不区分。
- **二次验证**：✅ 已复跑确认（探针 `d3_agent_memory_no_gate`，对照 `d3_control_human_memory_persists` 通过）。
- **注意**：`evolution.py:21-22` 声称"长期指令文件始终需审批"，但该不变量**只覆盖 EvolutionEngine**，任何持有 `MemoryStore` 的代码写入即生效 —— 属于**语义缺口/文档漂移**。

### 🟠 QA-04 · 子 Agent 事件折叠绕过注入净化 — P1（安全）

- **触发条件**：子 Agent 产出含指令形态文本的**事件**（非 `report.text`），例如 `<system>ignore ...</system>`。
- **实际结果**：折叠进父级 `self.events` 时**只做 260 字符截断，不做 `sanitise_child_output`**；父级共享同一 session，原始文本落盘。
- **预期结果**：所有进入父级上下文/事件流的子代文本都应过 `INJECTION_RE`。
- **证据**：`forge/loop.py:542-548`（折叠循环）vs `forge/loop.py:559`（`clean = sanitise_child_output(report.text)`）。全文件 `sanitise_child_output` **仅 1 处调用**（第 559 行）。
- **二次验证**：✅ 已复跑确认。探针 `qa_regression/probe_sanitise.py` 输出 `payload survived folding unredacted=True`，同时对照项证明净化器本身有效（`sanitised='[redacted-directive]...'`）。
- **连带**：`development/runtime.py:263-266` 从事件重建 `history` 并回灌，同样无净化 —— 已确认的次级路径。

### 🟠 QA-05 · Checkpoint 回滚不删除快照后新建的文件 — P1

- **触发条件**：`snapshot()` → 新建文件 → `rollback(commit)`。
- **实际结果**：已跟踪文件正确还原（对照项通过），但**快照之后新建的文件残留**。
- **预期结果**：回滚应恢复到快照时刻的工作区状态（或明确声明"仅还原已跟踪文件"）。
- **证据**：`forge/checkpoint.py:106-111` 使用 `git checkout <commit> -- .`，该形式只重写已跟踪路径，从不删除快照后的新增文件（无 `git clean`）。
- **二次验证**：✅ 已复跑确认（探针 `d1_rollback_residue`，输出 `tracked restored='v1'; post-snapshot file still present=True`；对照 `d1_control_rollback_restores` 通过）。
- **注意**：`selftest.py:401-409` 只断言"已存在文件被还原"，**未覆盖新建文件**，因此 569/569 全绿掩盖了该缺口。

### 🟠 QA-06 · 全局密钥脱敏注册表污染，导致合法标识符被拒 — P1

- **触发条件**：进程内任意位置调用过 `MemorySecretStore._put()`（`forge/secrets.py:131` 无条件 `_remember(value)`）→ 该值永久进入模块级全局 `_KNOWN`。
- **实际结果**：`redact()` 对后续**任意**文本做子串匹配。实测运行 `tests/test_development_loop.py` 后，普通单词 `'old'` 被脱敏成 `[REDACTED_SECRET]`；进而 `ModeState._validate_role` 因 `redact(list(pair)) != list(pair)` 抛出 `ValueError: Model identifiers must not contain credentials`，**合法的模型标识符被拒绝**。
- **预期结果**：脱敏注册表应有作用域（按 session/scope）与生命周期；普通词不应污染全局。
- **证据**：`forge/secrets.py:21-26`（全局 `_KNOWN`）、`71-84`（`_remember` 只增不减）、`86-104`（`_known_text` 子串匹配）、`state.py:124-125`。
- **二次验证**：✅ 已复跑确认（`qa_regression/probe_redaction_leak.py`：`_KNOWN` 由 0 增至 14；`redact('old') -> [REDACTED_SECRET]`）。
- **第二处独立表征（更严重）**：同一根因会让**配置编辑被误拒** —— 见 §3.2 证据链，把 `/model` 从 `'old'` 改为 `'new'` 触发 `PermissionError: Protected secret cannot be removed, replaced or swapped`。这说明污染不止影响显示层脱敏，还会**阻断正常的配置写入**。
- **影响面**：该缺陷是当前 pytest **8 项稳定失败的唯一根因**（§3.2 表 1、3-8）。修复它可一次性转绿 8 个用例。
- **锁的事实**：`_KNOWN` 的变更点确实都持有 `_LOCK`，进程内无数据竞争；问题在**生命周期与作用域**，不是加锁问题。

### 🟡 QA-07 · 多 Session 写入同一文件产生重复 ordinal — P2

- **触发条件**：两个 `Session` 对象打开同一 path 并各自 append。
- **实际结果**：两边内存序号都从 1 开始 → ordinal 重复（实测 `[1, 1]`），破坏了"单调递增 ordinal"这一文档化契约（`session.py:5`）。
- **预期结果**：ordinal 全局唯一单调，或并发写入被显式拒绝。
- **证据**：`forge/session.py:162`（`ordinal` 由内存列表推导）、session.py 未引入 threading。
- **二次验证**：✅ 已复跑确认（探针 `probe_defects2.py::d4_concurrent_session_ordinals`，两项对照通过）。
- **缓解事实**：spawn 路径中父子树共享同一个 `Session` 对象（`loop.py:510`），单进程单树不触发；多进程 / GUI 与 Runtime 双开才触发。

### 🟡 QA-08 · Tool Registry 重名静默覆盖且无注销入口 — P2

- **触发条件**：连续注册两个同名 tool。
- **实际结果**：后者静默覆盖前者，无告警；`ToolRegistry` 无 `unregister()`；`register()` 不做名称校验（接受含空格的名字）。
- **预期结果**：重名应显式报错或拒绝；插件卸载应有注销路径。
- **证据**：`forge/tools.py:85-86`（`self._specs[spec.name] = spec`）。
- **二次验证**：✅ 已复跑确认（`probe_tools.py`，现已修正为"观测型"断言）。
- **定性**：当前内置工具集无重名，属**潜伏风险**而非活跃故障。

### 🟡 QA-09 · `sys.modules` 全局污染 / 能力根目录累积 — P2

- **触发条件**：多次构造 `ModuleRegistry` 并 `discover()`。
- **实际结果**：`registry.py:782` 以 `forge_contrib_<stem>` 键写入进程级 `sys.modules`，后建者覆盖，且无清理路径；`capability.py:215` 每次 `install()` 都向 `self.roots` 追加，重复安装累积重复根。
- **证据**：`forge/registry.py:776-788`、`forge/capability.py:215`。
- **二次验证**：⚠️ 源码已核实，**未在本轮动态复现**（低危，无越权/崩溃风险）。

### 🟡 QA-10 · 测试脚本缺陷：symlink 断言在本主机不可执行 — P2（测试侧，非业务代码）

- **触发条件**：Windows（未开启开发者模式）上 `Path.symlink_to()`。
- **实际结果**：`symlink_to()` **不抛异常**，而是静默创建一个 **0 字节普通文件**，`is_symlink()` 为 `False`，`S_ISLNK` 为 `False`，`st_file_attributes` 无 `FILE_ATTRIBUTE_REPARSE_POINT`，`os.readlink` 报"不是一个重分析点"。因此逃逸根本没发生，但测试的 `except OSError: skipTest` 守卫拦不住，断言 `PermissionError` 失败。
- **预期结果**：守卫应先校验 `link.is_symlink()`，否则跳过。
- **影响范围**：`tests/test_development_mode.py:141-150`、`forge-gui/test_plugin_capabilities.py:96-109`（两处同样的不足守卫）。
- **定性**：**测试脚本缺陷**。业务侧 `ProjectBoundary.path()`（`editor.py:25-31`）确实先用 `.resolve()` 再判 `is_relative_to`，绝对越界路径的对照项被正确拒绝 —— **未发现真实的 symlink 越权**。

## 5. 建议优先修复的问题

### 第一优先（P0，建议在下一集成窗口内修复）

1. **QA-01** — `apply(force=True)` 绕过审批闸门
   最小改法：`force` 仅豁免 `evaluate()=="quarantined"` 的软条件，`requires_approval==True` 时无条件拒绝；或给 `force` 增加宿主签名参数。
2. **QA-02** — `approve(by=...)` 身份可伪造
   最小改法：`by` 改为宿主注入的枚举/凭证，不为自由字符串；`apply` 校验 `decision_by` 来源。

> 两者当前无活跃利用路径（`EvolutionEngine` 未挂到 Agent 工具面），因此是**修复窗口**而非**线上事故**；但一旦接上工具面即成真实提权通道，建议在接入前修完。

### 第二优先（P1）

3. **QA-04** — 子代事件折叠补 `sanitise_child_output`（`loop.py:542-548`），并覆盖 `runtime.py:263-266` 的恢复回灌路径。**改动最小、安全收益最高，建议最先做。**
4. **QA-05** — Checkpoint 回滚补 `git clean` 语义（或显式声明并修正文档）；同时补一条"快照后新建文件"的自检用例（`selftest.py:401-409` 旁）。
5. **QA-03** — `MemoryStore.recall/context_slice` 与 `KnowledgeBase.search` 区分 `source`，agent 条目需固化后才生效。
6. **QA-06** — 给 `_KNOWN` 增加作用域与生命周期（按 `SecretScope` 隔离 + 可清理），避免普通词永久污染全局。
   > **性价比最高的一项**：它是当前 pytest 8 项稳定失败的**唯一根因**，修完可一次性转绿 8 个用例，并同时消除"合法模型标识符被拒"与"合法配置编辑被拒"两类误伤。
