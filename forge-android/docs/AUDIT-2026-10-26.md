## 协议与验证闭环

设备请求现在带有 `run_id/task_id/parent_run_id`，`call_id` 仍是设备回执关联键；核心动作日志保留独立 action_id。
调用参数在 Python 与 Kotlin 两侧分别校验；宿主授权不替代核心 Policy。
`ui.input` 明确是替换当前焦点字段，不是追加键盘输入。操作后重新观察用于确认效果，手势完成回调不是业务成功证明。
兼容旧的合法布尔回执和可选 execution_state；字符串真假值与矛盾成功状态现在被拒绝。

新增真实 Agent 离线闭环：通过真实 ModelRouter/Agent/ToolRegistry/Session 调用 android.device.info，
模拟宿主回传后生成最终答案，并检查日志内设备数据、tool_completed 与 run 身份关联。
模型 transport 与 Android 宿主在该测试中使用夹具，不能视为真机或线上模型验证。

## 限制及后续

1. 本机 adb 未连接 Android 设备。Accessibility 手势、实际权限弹窗、Shizuku Binder、PRoot/SELinux 和旋转/分屏仍须真机验收。
2. 截图虽然有尺寸与坐标说明，但共享 Agent 目前仍以文本工具结果消费 PNG 数据，并未建立多模态图片注入。
   本轮没有宣称“模型已能看懂手机截图”。优先采用 UI 树定位，旋转后必须重新观察。
3. 取消不能保证已派发输入回滚；结果未知不会自动重试。回执重发与设备动作重放是两条不同链路。
4. 页面树变化仍采用保守拒绝，动态界面可能需要重新观察并批准；尚未引入稳定元素ID或观察快照绑定的点击协议。
5. 工具能力在运行开始时形成暴露快照；新增能力从下一轮生效，撤销在当前轮派发前生效。
6. 本轮未调用付费模型或外部账号，未遍历仓库所有独立测试套件。
